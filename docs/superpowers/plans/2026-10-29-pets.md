# Pets (Mel e Thor) — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Perfis dos cachorros com registros veterinários, nas mesmas telas da família, separados por uma divisória "Pets".

**Spec:** `docs/superpowers/specs/2026-10-29-pets-design.md` — fonte dos textos, campos e regras. Depende do perfil com foto (já feito: `editarPessoa`, `FotoDoPerfil`, `useFormPerfil`, `DEditarPerfil`, `EditarPerfil` mobile).

**Architecture:** Pet é uma `Pessoa` com `tipo: 'pet'` e `pet: DadosPet`. Registros novos (vacina, prevenção, sintoma, procedimento, pesagem) são entidades no `State`, criadas por eventos append-only. Seletores separam família e pets. Formulários com lógica em hooks em `src/data/formularios.ts` e apresentação desktop (kit `DDialogo`) e mobile (estilo M06/M18).

## Global Constraints

- Textos pt-BR conforme a spec. Tokens de `src/styles/tokens.css`. Sem dependências novas, sem rede, sem ícones novos.
- Estado só por `api.*` (eventos append-only). Nada em claro no disco.
- Pets não entram em compartilhamento: `podeVer` sempre verdadeiro para pets; `editaveis` inclui pets; ficam fora da matriz D07/M13.
- Divisória "Pets": rótulo mono 11 px caixa alta `--text-3` + linha `--divider`. Componente único reutilizado.
- Telas existentes de pessoas não mudam além do necessário para agrupar/filtrar pets.
- `npm run build` limpo e `npm test` passando a cada tarefa. Fim de linha preservado. Commits terminam com linha em branco + `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Não adicionar `.superpowers/`.

### Task 1: Modelo de dados, eventos, seletores e dados de exemplo

**Files:** `src/data/types.ts`, `src/data/store.tsx`, `src/data/pets.ts` (novo: seletores e funções puras), `src/data/pets.test.ts`, `src/data/seed.ts`.

**Produces:**
- Tipos: `Pessoa.tipo?: 'pessoa' | 'pet'`, `Pessoa.pet?: DadosPet` (`especie: 'cachorro'`, `raca?`, `castrado?`, `microchip?`, `veterinario?: { nome; clinica?; telefone? }`, `clinica24h?: { nome; telefone }`); `Vacina`, `Prevencao`, `Sintoma`, `Procedimento`, `Pesagem` conforme a spec; `State` ganha `vacinas`, `prevencoes`, `sintomas`, `procedimentos`, `pesagens` (arrays; estado base e exemplo inicializados).
- Eventos/`api`: `addVacina`, `addPrevencao`, `addSintoma`, `addProcedimento`, `addPesagem` (evento `pesagem`). `editarPessoa` já aceita `pet` no patch (confira o tipo `PatchPessoa`).
- `pets.ts`: `ehPet(p)`, `familia(s)`, `pets(s)` (ordem de cadastro), `pesoAtual(s, petId): Pesagem | undefined`, `proximaPrevencao(p: Prevencao): string` (ISO), `ultimasPrevencoes(s, petId)` (a mais recente por tipo+produto), `vacinasDoPet`, `sintomasRecentes(s, petId, dias)`, `SINAIS` (lista fixa), `TIPOS_PROCEDIMENTO`, `SUGESTOES_VACINA`.
- `podeVer`/`compartilhado`: pet → todas as categorias. `editaveis`: inclui pets.
- Seed: Mel e Thor com os dados da seção "Dados de exemplo" da spec (raças à sua escolha plausíveis — ex.: Mel, vira-lata caramelo, fêmea, castrada; Thor, shiba inu, macho, castrado). Os ids `mel`/`thor`.
